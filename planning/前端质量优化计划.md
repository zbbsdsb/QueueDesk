## 🔴 P0 — 必须修复（阻塞后续开发）

### P0-1: 提取共享工具函数到 `src/lib/utils.ts`

**问题**: `timeAgo` / `formatDate` / `getAge` 在以下文件中重复定义：
- `src/app/(agent)/agent/dashboard/page.tsx`
- `src/components/agent/TicketsTable.tsx`
- `src/components/agent/TicketDetail.tsx`
- `src/app/(app)/app/tickets/page.tsx`
- `src/app/(app)/app/tickets/[id]/page.tsx`
- `src/app/(admin)/admin/users/page.tsx`
- `src/app/(admin)/admin/teams/page.tsx`
- `src/app/(admin)/admin/queues/page.tsx`
- `src/app/(admin)/admin/sla/page.tsx`

**方案**:
1. 创建 `src/lib/utils.ts`，统一导出 `timeAgo(date)` 和 `formatDate(date)`
2. 全局替换各文件中的局部定义 → `import { timeAgo } from "@/lib/utils"`

**预估时间**: 30min

---

### P0-2: 修复 `as unknown as` 双重类型断言（12 处）

**问题**: 完全绕过 TypeScript 类型检查

| 文件 | 行号 | 当前写法 |
|------|------|----------|
| `TicketsTable.tsx` | ~199 | `as unknown as Ticket[]` |
| `TicketDetail.tsx` | ~100 | `as unknown as TicketDetail` |
| `TicketDetail.tsx` | ~114 | `as unknown as Comment[]` |
| `app/tickets/page.tsx` | ~79 | `as unknown as TicketWithRelations[]` |
| `app/tickets/[id]/page.tsx` | 多处 | `as unknown as Ticket...` |
| `agent/settings/page.tsx` | 多处 | `as any` (×3) |
| `agent/tickets/new/page.tsx` | 多处 | `as any` (×2) |
| `api/cron/sla/route.ts` | ~105-106 | `queue as any`, `agent as any` |
| `client.ts` | ~5 | `{ [key: string]: any }` |

**方案**:
1. 为每个 Supabase 查询定义精确的返回类型（基于 `select` 字段）
2. 或使用 Supabase 的 `InferOutput<typeof query>` 泛型
3. 删除所有 `eslint-disable` 注释

**预估时间**: 2h

---

### P0-3: 提取 `ShellLayout` 共享组件

**问题**: 三个 Shell 组件结构几乎相同（~370 行重复代码）

| 组件 | 行数 | 差异点 |
|------|------|--------|
| `AgentShell.tsx` | 156 | nav items、标题、角色条件 |
| `AppShell.tsx` | 121 | nav items、标题 |
| `AdminShell.tsx` | 94 | nav items、标题 |

**方案**:
1. 创建 `src/components/shared/ShellLayout.tsx`，接收 `navItems`, `title`, `onLogout` 等 props
2. 各 Shell 瘦化为配置文件 + `<ShellLayout />` 调用
3. 可选：进一步抽取 `<Sidebar />`, `<Header />` 子组件

**预估时间**: 1h

## 🟡 P1 — 应当修复（质量提升）

### P1-1: 修复 `AuthProvider.loading` 硬编码

**问题**: `AuthProvider.tsx` 第 52 行 `loading: false` 永远为 false

**方案**:
```typescript
const [loading, setLoading] = useState(true);
// 在 onAuthStateChange 首次回调后:
setLoading(false);
```

**预估时间**: 15min

---

### P1-2: 添加基础无障碍支持

**方案**:
1. `Modal.tsx` — 添加 `role="dialog"`, `aria-modal`, 焦点陷阱, `aria-labelledby`
2. 侧边栏导航 — 添加 `aria-current="page"` 到当前活跃链接
3. 表单输入 — 添加 `aria-label` 或 `<label htmlFor>`
4. Toast — 添加 `role="status"`, `aria-live="polite"`
5. 按钮 — 确保所有交互元素有可访问名称

**预估时间**: 2h

---

### P1-3: Dashboard 数据获取迁移到 Server Component

**问题**: `agent/dashboard/page.tsx` 610 行，8 个 Supabase 查询全部在客户端 `useEffect`

**方案**:
1. 页面级数据获取移到 Server Component
2. 子组件 (`StatCards`, `Charts`, `RecentTickets`) 接收 props
3. 需要将 supabase server client 传递到 Server Component

**预估时间**: 2h

---

### P1-4: 提取共享 `Avatar` 组件

**问题**: `app/tickets/[id]/page.tsx` 内联定义了 Avatar 组件，其他地方也用到了头像展示

**方案**: 创建 `src/components/shared/Avatar.tsx`

**预估时间**: 30min

---

### P1-5: 修复 `AnyClient` any 类型

**问题**: `client.ts` 使用 `{ [key: string]: any }` 扩展 Supabase client 类型

**方案**: 用 `unknown` + 类型守卫替代，或用 `satisfies` 约束

**预估时间**: 30min
